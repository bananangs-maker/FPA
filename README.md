# FPA

제조업의 제품·공장·월별 손익을 계산하는 단일 사용자용 시뮬레이터입니다.
현재 배포 버전의 원본 HTML 및 검산 코드입니다. 실제 데이터를 입력할 수 있는 빈 양식으로 시작합니다.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 화면·계산 엔진·백업 기능을 포함한 독립 실행 프로그램 |
| `render.yaml` | Render Blueprint 배포 설정 |
| `server.cjs` | Node.js 환경에서 HTML을 제공하는 경량 서버 |
| `package.json` | 실행 및 검산 명령 |
| `verify.cjs` | 배부·재고·손익·백업 등 77개 검산 |
| `.gitignore` | 환경설정·백업 폴더 등을 Git 대상에서 제외 |
| `.nojekyll` | 정적 HTML 서비스용 빈 파일 |

## Git에 업로드

ZIP을 풀고 **폴더 안의 파일 전체를 저장소 최상위에 업로드**하세요. ZIP 자체를 올리면 소스로 배포되지 않습니다.
`index.html`과 `package.json`이 최상위에 있어야 합니다. `.git` 및 기존 호스팅 서비스의 식별 정보는 포함하지 않았습니다.

새 저장소의 프로젝트 폴더에서 터미널로 업로드한다면 다음 순서입니다.

```bash
git init
git add .
git commit -m "Initial FPA source"
git branch -M main
git remote add origin <사용자_Git_저장소_URL>
git push -u origin main
```

기존 저장소라면 해당 저장소의 브랜치와 파일 구성을 확인한 뒤 파일을 복사합니다.

## 실행

`index.html`을 브라우저에서 바로 열 수 있습니다. 외부 라이브러리나 인터넷 연결은 필요하지 않습니다.

Node.js 서버를 사용할 경우 Node.js 20 이상에서 실행합니다. 외부 npm 의존성이 없어 설치 과정 없이 실행됩니다.

```bash
npm start
```

접속 주소는 `http://localhost:8080`입니다. 호스팅 환경이 `PORT`를 제공하면 해당 포트로 실행됩니다.
시작 명령은 `npm start`, 상태 확인 경로는 `/health`입니다. 정적 호스팅이면 최상위 `index.html`을 서비스하면 됩니다. 별도 빌드는 없습니다.

## 검산

```bash
npm test
```

USD/KRW 구분, 수율과 BOM, 2단계 배부, 재고 이월, 감가상각 비용 반영, 연간 가중 비율, 백업 데이터 형식 등 77개 항목을 확인합니다.
브라우저 상호작용 전체를 자동으로 검사하는 테스트는 아닙니다.

## 기능

- 제품별 1~12월 손익, 품목·전사·매출 집계
- 수량·단가·환율·생산량·수율·BOM·노무비·유틸리티 입력
- 공통 → 공장 → 제품 배부 및 공장·제품 직접비 귀속
- 제조·판관고정비, 운반·포장비 계산
- 기초재고와 월별 총평균법에 의한 매출원가·재고 이월
- 시나리오·CASE 복제, 계획/실적/추정 구분, 변수 일괄 조정 및 비교
- 브라우저 저장, JSON 백업·복원, CSV 출력, 현재 데이터를 포함한 HTML 내보내기
- 재고 부족·BOM 비율·미배부 비용 검산

## 데이터 및 접근 방식

입력값은 브라우저 localStorage에 저장되며 서버 DB는 없습니다. 기기·브라우저·접속 주소가 달라지면 자동으로 공유되지 않으므로 JSON 백업으로 이동합니다.
서버는 HTML만 제공하고 입력 데이터를 수신하는 API를 제공하지 않습니다.

기존 ChatGPT 사이트의 로그인 보호는 이 패키지에 포함되지 않습니다. 별도 호스팅 시 이 코드 자체에는 로그인·권한 관리가 없습니다.
입력값을 포함해 내보낸 HTML 및 JSON 백업은 Git 소스와 분리해 보관하세요. 제공한 `index.html`에는 예시 제품·수량·단가·환율·비용 금액이 없습니다. `verify.cjs` 안의 가상 데이터는 검산 전용이며 앱의 기본 데이터로 사용하지 않습니다.

## 계산 기준

- 총투입량 = 양품 생산량 ÷ 수율
- 자재비 = 총투입량 × 투입비율 × 적용 원화 단가
- 당월 제조원가 = 재료비 + 노무비 + 제조경비
- 매출원가 = 판매량 × (기초재고액 + 당월 제조원가) ÷ (기초수량 + 생산량)
- 영업이익 = 매출액 − 매출원가 − 판관비
- EBITDA = 영업이익 + 매출원가에 반영된 제조감가 + 판관감가
- 연간 이익률은 연간 합계로 재계산

재료비·노무비·제조경비 행은 당월 발생액이며 재고 증감을 거쳐 매출원가로 연결됩니다.
재공품·부산물·표준원가차이·공정 간 대체, ERP 자동 연동, 공동 편집은 현재 버전에 포함하지 않습니다.

## SITE 목록 편집

**기준정보 → 공장·제품** 화면에서 관리합니다.

- 제품이 없는 SITE도 먼저 등록할 수 있습니다.
- SITE명을 바꾸면 현재 CASE의 제품과 공장 직접 비용 풀에 함께 반영됩니다.
- 사용 중인 SITE를 삭제할 때는 연결된 제품과 직접 비용 풀을 다른 SITE로 옮깁니다. 월별 수량·단가와 비용 금액은 유지합니다.
- 제품 표의 SITE는 등록된 목록에서 선택합니다. 제품 하나만 옮기면 공장 직접 비용 풀은 기존 SITE에 유지됩니다.
- SITE 목록은 CASE별로 독립 저장되며 복제·JSON 백업에 포함됩니다.
- 구버전 저장 데이터와 JSON 백업은 제품 및 공장 직접 비용 풀의 SITE를 모아 자동으로 목록을 구성합니다.

## 화면 구성

다섯 개 주 메뉴에 기존 상세 기능을 모두 포함합니다.

| 메뉴 | 상세 기능 |
| --- | --- |
| 손익 | 한눈에 보기, 월별 손익, 제품별 비교, 재고·매출원가, 검산 |
| 매출·생산 | 매출 입력, 생산·수율, 매출 집계 |
| 제조원가 | 재료비, 노무비, 유틸리티, 수선·소모품, 제조고정비, 제조 집계 |
| 판관비 | 판관고정비, 운반·포장, 판관 집계, 배부 기준 |
| 기준정보 | 공장·제품, 시나리오 설정, 계산·사용법 |

- **처음 시작하기**: 다섯 단계 입력 흐름과 각 화면으로 바로 이동합니다.
- **기능 찾기**: 기능명 또는 수율·배부 같은 관련 용어로 검색합니다. 단축키는 Ctrl/Cmd+K입니다.
- **되돌리기**: 현재 시나리오의 입력을 최대 20개 기록 범위에서 되돌립니다. 기록은 현재 실행 중 메모리에만 있으며 새로고침 시 지워집니다.
- **표 보기 설정**: 표를 확대하거나 행 간격을 바꿉니다. 확대는 Esc로 종료합니다.
- **입력 이동**: Tab은 다음 셀, Enter는 다음 행으로 이동합니다. 붙여넣기와 재계산 후에도 표 스크롤을 유지합니다.
- **도움말**: 현재 화면의 입력 기준·계산식을 확인합니다. 일반 설명은 기본 화면에서 숨기고 검산 경고는 표시합니다.
- **파일**: JSON 백업·복원, HTML 다운로드, CSV 출력과 인쇄를 제공합니다.

화면과 이름을 변경하면서 손익 항목과 계산·배부·시나리오 기능은 유지합니다. 이번 실사용 양식은 별도 브라우저 저장 영역을 사용하므로 이전 예제가 자동으로 다시 표시되지 않습니다. 이전 저장 영역은 자동 삭제하지 않으며, 기존 JSON 백업은 파일 메뉴에서 불러올 수 있습니다.

## 시나리오 설정

상단 작업 시나리오 옆 **설정** 또는 **기준정보 → 시나리오 설정**에서 확인합니다.

- 기준 시나리오를 CASE별로 지정하고 **기준값 / 현재값 / 변동**을 비교합니다. 새로 복제한 CASE는 복제한 원본을 기준으로 연결합니다. 기존 CASE는 기준을 직접 선택할 수 있습니다.
- 현재값은 별도 가정표가 아닌 실제 입력 데이터에서 읽으므로 개별 셀 변경도 반영됩니다.
- 매출·생산·수율·BOM·재료 단가·환율·유틸리티·노무·고정비·배부 기준·기초재고를 확인합니다. 공장·제품·월·변수 구분·검색·변경 항목 필터를 지원합니다.
- 수율·비율 변화는 %p, 일반 수량·단가 변화는 기준 대비 %로 구분합니다. 통화와 배부 방식에 따라 계산에 쓰지 않는 입력은 기본적으로 숨기며 미적용 입력 포함으로 확인할 수 있습니다.
- **열기**로 해당 변수의 입력 화면으로 이동합니다. **손익 비교**로 같은 기준 CASE의 손익 차이를 확인합니다.
- 표는 50개씩 표시하며 **전체 CSV**는 현재 필터의 전체 변수를 내보냅니다.
- **일괄 조정 기록**은 이번 버전에서 실행한 요청부터 최대 1,000건 저장합니다. 기존 조정의 과거 요청 내역은 복원하지 않으며 현재 값의 차이는 확인할 수 있습니다.
- 변수 조정은 항목별 고정 기준을 사용합니다. 1%를 다시 적용해도 누적되지 않으며 1%→2%로 바꾸면 최초 조정 기준의 2%가 적용됩니다. 과거 버전에서 생성된 누적 조정 기록은 그대로 유지합니다.
- 기준값은 선택한 CASE의 현재 입력값입니다. 복제 시점에 고정한 스냅샷이 아니므로 기준 CASE를 수정하면 비교도 갱신됩니다. 비교 대상은 두 CASE의 공통 식별자를 기준으로 연결하며 신규·삭제 항목은 별도로 표시합니다.
- 기준 연결과 일괄 조정 기록은 JSON 및 데이터 포함 HTML에 함께 저장됩니다. 기존 백업도 계속 불러올 수 있습니다.

## 세부 변수 조정

**변수 조정** 창에서 공장·제품과 1~12월 중 적용할 기간을 선택합니다.

- 판매량과 생산량, 판매 단가와 매출 환율, 자재별 단가·환율·투입비율을 각각 조정합니다.
- 전력·스팀/가스·연료·용수는 각각 사용량과 단가를 따로 설정합니다.
- 노무비는 등록한 조직별, 제조·판관고정비는 등록한 계정별로 각각 조정합니다. 수선·소모품, 운반·포장, 기초재고도 별도 항목입니다.
- 기본 화면에는 비용 계정을 표시합니다. **배부·귀속 조건 포함**을 켜면 배부 기준·비용 귀속·대상·계정명도 변경할 수 있습니다. 통화상 비활성 단가·환율은 **미적용 금액 입력 포함**으로 확인합니다.
- 증감 %, 증감 %p, 증감값, 값 지정 중 해당 항목에 맞는 방식을 사용합니다. 환율을 1,450원으로 맞추려면 값 지정을 선택합니다.
- **조정 기준값 / 현재값 / 저장된 방식·조정값**을 함께 확인합니다. 설정은 제품·월별 실제 입력에 연결되며 새로고침·복제·백업에도 유지됩니다.
- 1%를 2%로 바꾸면 최초 기준 × 1.02가 됩니다. 0%는 최초 기준으로 복원하며 -100% 적용 후에도 되돌릴 수 있습니다.
- 범위 내 조정 설정이 다르면 **범위 내 값 다름**으로 표시합니다. 입력하지 않은 항목은 유지하며, 다른 범위로 이동해 작성한 대기 설정도 함께 적용합니다.
- 표에서 직접 수정한 셀은 그 수정값이 새 조정 기준이 됩니다. 다른 셀의 기준과 설정은 유지합니다.
- 조정 기준은 최초 조정 시 입력값에 고정됩니다. 시나리오 설정 화면의 비교 기준 CASE는 별개이며 현재 비교 대상 값을 읽습니다.
- 공장 선택은 해당 공장 직접비, 제품 선택은 해당 제품 직접비만 포함합니다. 전사 공통비 조정은 전체 공장·제품 범위에서 합니다.
- 과거 변화율 기록과 비교 CASE가 있으며 현재 입력값이 계산 결과와 일치하는 항목은 이전 변화율을 복원합니다. 추정할 수 없는 항목에는 임의 변화율을 만들지 않습니다.

## 엑셀처럼 범위 입력

1. **열 제목 클릭**: 현재 화면의 해당 열 전체를 선택합니다. 환율을 12개월 모두 바꾸려면 월 필터를 **1~12월 전체**로 먼저 바꿉니다.
2. **범위 선택** 버튼: 켠 뒤 셀을 드래그하거나, 시작 셀 클릭 후 Shift+클릭으로 사각 범위를 선택합니다.
3. **Ctrl+클릭**(맥 ⌘): 떨어진 셀이나 열을 추가·해제합니다.
4. 하단 입력창에서 숫자·통화를 지정하고 **같은 값 적용**을 누릅니다. 통화 열은 USD/KRW 목록에서 선택합니다.
5. **선택 해제** 또는 Esc를 누르면 일반 개별 입력으로 돌아갑니다.

표시 중인 제품·월에만 적용하며 계산 결과 열은 변경하지 않습니다. 여러 셀의 형식과 범위를 모두 확인한 뒤 한 번에 저장하므로 오류가 있으면 일괄 변경하지 않습니다. 한 번의 되돌리기로 전체 일괄 입력을 복원할 수 있습니다. 선택 셀 복사와 엑셀의 탭·줄바꿈 붙여넣기도 지원합니다.

FPA 로고의 코발트 블루 점은 4초 주기로 천천히 점멸합니다. 움직임 줄이기 설정에서는 정지 표시됩니다. 이는 앱 실행 표시이며 서버 연결 상태를 뜻하지 않습니다.

## 실사용 시작

- 기본 CASE는 **2027 경영계획 / BASE** 한 개입니다. 예시 제품·자재·수요 둔화 CASE와 과거 조정 기록은 없습니다.
- **공장 등록** 또는 **기준정보 → 공장·제품 → + 공장 추가**에서 실제 제품을 추가합니다. 기본 SITE 목록은 비어 있습니다. 먼저 공장을 직접 등록한 다음 제품을 추가합니다.
- 새 제품의 12개월 매출·생산·수율·환율·원가 입력은 모두 빈칸입니다. 자재와 비용을 새로 추가해도 임의 환율·단가·금액을 넣지 않습니다.
- 판관비 21개 계정은 1~12월에 그대로 준비하고 금액만 비웠습니다. 제조고정비의 표준 계정도 금액 없이 준비합니다. 실제 노무 조직은 노무비 화면에서 추가합니다.
- 빈칸은 미입력이고 `0`은 명시적으로 입력한 0입니다. JSON 백업·복원에서도 이를 구분합니다. 빈칸 상태는 저장 및 다음 화면 이동을 막지 않습니다.
- 생산량이 있는데 수율이 없거나 판매량이 있는데 단가·환율이 없으면 검산 경고를 표시합니다. 누락 입력을 100% 수율이나 임의 환율로 대체하지 않습니다.
- 기준값이 없는 항목은 변수 조정의 **값 지정**으로 실제 값을 먼저 입력합니다. 이후 증감률을 적용할 수 있습니다.
- 데이터 초기화는 예제를 다시 채우지 않고 이 빈 양식으로 돌아갑니다. 자동으로 실사용 입력을 지우지는 않습니다.

## 배포 데이터 점검

최신 배포 HTML과 이 패키지는 회사·사업장·산업을 특정하는 기본 데이터를 포함하지 않습니다. 공장·제품·자재·노무 조직은 비어 있으며 제조·판관비의 일반 계정명과 계산 기능을 제공합니다. 검산 파일의 공장·제품·자재·직무 표기는 중립적인 가상 값입니다.

앱은 외부 스크립트·폰트·분석 도구를 불러오지 않으며 입력값을 업로드하는 API를 사용하지 않습니다. 문서의 콘텐츠 보안 정책으로 외부 통신을 차단합니다. 이 패키지의 Node 서버도 GET/HEAD 요청으로 정적 파일만 제공하며 데이터 저장 API는 없습니다.

사용자가 직접 실행한 JSON·CSV·데이터 포함 HTML 저장에는 입력 데이터가 담깁니다. 이를 저장소에 업로드하거나 다른 사람에게 전달하면 그 파일 안의 데이터도 전달됩니다. 브라우저 저장은 기기 내부 저장이며 별도 암호화를 제공하지 않습니다.

이번 버전은 새로운 빈 저장 영역을 사용합니다. 이전 버전의 브라우저 데이터·다운로드·원격 저장소 이력은 이 패키지에 포함하지 않으며 자동으로 영구 삭제하지 않습니다.

## Render Blueprint 배포

1. ZIP을 풀고 `render.yaml`, `index.html`, `package.json`, `server.cjs`, `verify.cjs`와 나머지 파일을 GitHub 저장소 **main 브랜치 최상위**에 업로드하고 커밋합니다.
2. Render에서 연결한 저장소와 브랜치가 같은지 확인합니다. Blueprint 파일 경로는 `render.yaml`, Root Directory는 비워둡니다.
3. 기존 Blueprint 설정 화면을 새로고침하거나 다시 시도합니다. 새로 연결한다면 New → Blueprint에서 저장소를 선택합니다.
4. 설정 검토 후 배포합니다. 무료 Node 웹 서비스, 빌드 `npm test`, 시작 `npm start`, 상태 확인 `/health`가 설정되어 있습니다.

`render.yaml`을 ZIP 파일 안에만 두거나 `FPA_Studio_Git/render.yaml`처럼 하위 폴더에 올리면 기본 검색 위치에서 찾지 못합니다. 저장소 첫 화면에서 파일명 `render.yaml`이 직접 보여야 합니다.

이 설정 파일은 웹 서버 배포만 구성합니다. 로그인이나 서버 데이터베이스를 추가하지 않습니다. 앱 입력값은 기존처럼 각 브라우저에 보관됩니다.

## FPA 파비콘

흰 바탕, 검정 F, 코발트 블루 점으로 구성한 아이콘입니다. `favicon.svg`, 다중 크기의 `favicon.ico`, PNG 16·32·180·512px 파일이 들어 있습니다. HTML에는 SVG와 PNG 아이콘을 직접 포함해 독립 HTML로 열어도 표시됩니다. 외부 이미지나 폰트를 요청하지 않습니다.

Node 서버는 고정된 파비콘 경로만 제공합니다. 이전 버전에서 업데이트할 때는 `index.html`, `server.cjs`와 아이콘 파일을 포함한 전체 패키지를 같은 위치에 올리세요. `render.yaml`은 그대로 포함되어 있습니다.
